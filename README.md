# breast-cancer-ideal-K-algorythm
KNN Ideal K algorythm
Breast Cancer — классификация диагноза (доброкачественная/злокачественная опухоль)

Проект по анализу и классификации данных о раке молочной железы (Wisconsin Breast Cancer Dataset). Задача — предсказать диагноз (diagnosis: злокачественная M / доброкачественная B) по числовым характеристикам клеточных ядер, полученным из изображений тонкоигольной биопсии, с помощью классификатора K-ближайших соседей (KNN) и подбором оптимального гиперпараметра через GridSearchCV.

Описание

Датасет breast-cancer.csv — классический Wisconsin Diagnostic Breast Cancer (WDBC) датасет: 569 наблюдений, для каждого — 30 числовых признаков (среднее, стандартная ошибка и «худшее»/наибольшее значение для 10 характеристик клеточного ядра: радиус, текстура, периметр, площадь, гладкость и др.) и целевая переменная diagnosis. Данные уже чистые (без пропусков), поэтому ноутбук breast_cancel.ipynb фокусируется на подготовке признаков, обучении модели и подборе гиперпараметров.

Целевая переменная

diagnosis — диагноз: M (Malignant, злокачественная) или B (Benign, доброкачественная). Распределение классов: 357 доброкачественных, 212 злокачественных — умеренный дисбаланс классов.

Что делает ноутбук
1. Загрузка и подготовка данных
Столбец id удалён — не несёт диагностической информации.
Целевая переменная diagnosis закодирована через LabelEncoder (B → 0, M → 1).
2. Корреляционный анализ

Посчитана корреляция каждого числового признака с diagnosis (df.corrwith().abs().sort_values()). Наиболее сильно с диагнозом связаны: concave points_worst (≈0.79), perimeter_worst (≈0.78), concave points_mean (≈0.78), radius_worst (≈0.78), perimeter_mean (≈0.74) — то есть форма и размер ядра клетки наиболее информативны для диагностики.

3. Подготовка к обучению
Признаки (x) и целевая переменная (y) разделены на обучающую и тестовую выборки (train_test_split, test_size=0.25, random_state=42).
Признаки масштабированы через StandardScaler (обучен на x_train, применён к x_train и x_test).
4. Базовая модель

Обучен KNeighborsClassifier с n_neighbors=9.

5. Подбор числа соседей (k)
Построен график F1-score для k от 1 до 24 — для визуальной оценки, при каком k модель работает лучше всего.
Выполнена 5-fold кросс-валидация (cross_val_score) для оценки устойчивости модели.
Проведён подбор гиперпараметра через GridSearchCV (cv=5, перебор n_neighbors от 1 до 24).

Возможные улучшения
Модель после подбора не сохраняется в файл (joblib.dump) — стоит добавить сохранение лучшей модели (classifier_gscv.best_estimator_) для дальнейшего использования без повторного обучения.
В этой задаче важнее минимизировать ложноотрицательные диагнозы (пропущенный рак опаснее ложной тревоги) — стоит явно анализировать recall для класса M, а не только усреднённые метрики, и при необходимости настраивать порог классификации.
В графике «Mistake Rank» на оси Y отображается ранг (rank_test_score), а не сама метрика — для наглядности лучше строить график по значению accuracy/F1 (classifier_gscv.cv_results_['mean_test_score']), где видно не только порядок, но и величину различий между значениями k.
Признаки в датасете сильно скоррелированы между собой (например, radius, perimeter, area измеряют по сути одно и то же) — можно рассмотреть отбор признаков (feature selection) или снижение размерности (PCA) для упрощения модели.
Сравнить KNN с другими алгоритмами (логистическая регрессия, SVM, случайный лес, градиентный бустинг), которые часто показывают более высокое и стабильное качество на этом датасете.
Учесть дисбаланс классов (357 против 212) — например, через стратифицированное разбиение (stratify=y в train_test_split) или взвешивание классов.
